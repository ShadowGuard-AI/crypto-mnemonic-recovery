First entry: what was received

The program receives a partial BIP39 phrase in which each absent place is marked with a question mark. It tries candidate entries from the wordlist supplied by the mnemonic package in those marked places and in no others. It keeps only those completions for which the BIP39 checksum, applied through the package validation call, returns true, and it prints the completions it has kept. The method is named plainly: exhaustive replacement followed by checksum validation. A completion can be formally valid without being the phrase that any particular person once held.

Second entry: the shape of a submission

The partial phrase is divided on spaces. Its total count must be one of the recognised BIP39 lengths, which the code gives as 12, 15, 18, 21, or 24. Any other count ends the run with an error and exit 1 before a single candidate is formed. The number declared as missing must equal the number of question mark places actually present, and a disagreement likewise ends the run at exit 1. An absent partial phrase, which the parser itself does not require, is refused by the main routine with a printed instruction and exit 1.

Third entry: the controls in parser order

The partial phrase control is the submission itself, space separated, with a question mark standing in each absent place. The missing count control is an integer whose default is 0 and whose value must match the marks. The language control names the wordlist language, with english as its default and with no list of permitted values enforced by the parser. The attempt ceiling control is an integer whose default is 10000. The debug control is a flag which, when present, lowers the logging level so that the debug line announcing its own enabling is printed. There is no control by which a caller may supply a wordlist of their own: the wordlist always arrives from the mnemonic package in the language named.

Fourth entry: the arithmetic of the search

Each absent place multiplies the field of candidates by 2048. A single absent place yields a field small enough to be searched entire under the default ceiling. Two absent places yield a field of a little over four million candidates, of which the default ceiling admits only the first ten thousand, in the order in which the recursive generator produces them, before the run prints a notice that it has stopped and invites the caller to raise the ceiling. A two place search under the default settings is therefore not a completed search but an opening slice of one, and the closing line which reports that nothing could be recovered records only that no valid completion appeared among the candidates actually checked.

Fifth entry: what the search does not do

The program performs no fuzzy matching of any kind. It does not correct a known entry which has been misspelled, a failure which presents as an empty result rather than as a diagnosis. It cannot assist where the position of an absent entry is unknown, because only marked places are ever varied. It does not derive anything from a completion beyond testing the completion itself: the validation call is the checksum check supplied by the package rather than any seed derivation. Candidates are yielded one at a time and discarded as they are checked, so the field is never held entire in memory at once, although the validation object is rebuilt for each candidate in turn, wordlist and all.

Sixth entry: handling

This page prints no example completion, no example partial phrase drawn from any real or illustrative set, and no wordlist entry presented as part of a phrase, anywhere, in any panel. The output is described by its behaviour alone: kept completions are printed in full to standard output under a heading announcing them, a run which keeps none prints a single line saying so, and either ending, where no error has intervened, closes with an ordinary successful exit, so a caller who scripts around this tool must read its printed lines and cannot rely on the exit code to tell a fruitful watch from a fruitless one. The program itself writes nothing to any file and keeps no record once the run has ended, and the results a caller handles afterwards are theirs to guard.

# crypto-mnemonic-recovery

Recovers a BIP39 mnemonic phrase when some words are missing. Give the known words in order with `?` in each missing position; the tool tries every wordlist word in those positions and prints the completions whose BIP39 checksum validates.

That is the whole method: exhaustive replacement plus checksum validation. It does not do fuzzy matching, does not fix a misspelled known word, and cannot help if the position of a missing word is unknown. Each missing word multiplies the search by 2048, so one missing word is quick and three is not practical.

## Requirements

- Python 3
- The `mnemonic` package (see requirements.txt). Earlier requirements named `cryptography`, which this code does not use, and omitted the package it does use.

## Install

```bash
git clone https://github.com/ShadowGuard-AI/crypto-mnemonic-recovery.git
cd crypto-mnemonic-recovery
pip install -r requirements.txt
```

The live README usage block stands at this place in the original file. ## Parameters

- `--partial_mnemonic`: The partial phrase, space separated, with `?` for each missing word. The total word count must be 12, 15, 18, 21, or 24.
- `--num_missing`: Number of missing words; must equal the number of `?` entries.
- `--language`: Mnemonic language (default: english).
- `--max_attempts`: Maximum candidates to check before stopping (default: 10000).
- `--debug`: Enable debug logging.
